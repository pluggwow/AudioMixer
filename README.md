# AudioMixer

Нативный per-app аудиомикшер для macOS. Menu Bar, SwiftUI, Core Audio Process Taps.

## Требования

- **macOS 14.4+** — раньше нет `AudioHardwareCreateProcessTap` / `muteBehavior`
- Xcode 15.3+
- Apple Silicon и Intel (universal, `ARCHS_STANDARD`)

## Сборка

Вариант A — XcodeGen (рекомендуется):

```bash
brew install xcodegen
cd AudioMixer
xcodegen generate
open AudioMixer.xcodeproj
```

Вариант B — вручную: создать в Xcode новый **macOS → App (SwiftUI)**, удалить
шаблонные файлы, перетащить папку `Sources` (Create groups), подключить
`Resources/Info.plist` и `Resources/AudioMixer.entitlements`, выставить
deployment target 14.4 и **выключить App Sandbox**.

При первом запуске macOS запросит разрешение на захват аудио. Без него работает
только мастер-громкость; панель покажет баннер с кнопкой в Системные настройки.

## Архитектура

```
Views ──> ViewModels ──> Services / Audio ──> Core Audio
         (MixerViewModel)
```

Views не импортируют CoreAudio вообще. Единственная точка, где UI встречается с
аудиослоем, — `MixerViewModel`.

| Слой | Файлы | Ответственность |
|---|---|---|
| `Audio/` | `AudioProcessTapEngine` | таппы, агрегат, IOProc, gain |
| | `RenderState` | realtime-микс, единственный код на RT-потоке |
| | `AudioProcessMonitor` | список аудио-процессов через нотификации |
| | `AudioDeviceManager` | default output, список устройств |
| | `SystemVolumeController` | мастер-громкость реального устройства |
| | `PermissionManager` | проверка TCC пробным таппом |
| `Services/` | `VolumeStore` | персистентность по bundle ID |
| | `AppOrderStore` | ручной порядок строк |
| | `LoginItemService` | `SMAppService` |
| | `HotkeyService` | протокол-задел, реализации нет |

### Как работает per-app volume

Публичного API «задать громкость чужого процесса» в macOS нет. Реализовано так:

1. Приложениям, которым нужен перехват, создаётся `CATapDescription` с
   `muteBehavior = .mutedWhenTapped` — система сама глушит их оригинальный выход.
2. Тапп подключается входом к приватному aggregate device, main sub-device
   которого — устройство вывода. Агрегат **свой у каждого приложения**. Это и
   позволяет увести одно приложение в наушники, пока остальные играют в
   динамики, и — главное — делает их независимыми: список таппов задаётся
   только при создании агрегата, поэтому появление или снятие таппа = его
   пересборка, а в общем агрегате она рвала звук ВСЕМ, кто в нём был. Дёрнешь
   громкость одного — лагает музыка в другом.
3. В каждом агрегате свой IOProc: читает вход, умножает на gain, пишет в выход.

Гейн меняется не ступенькой, а линейным разгоном по сэмплам: `RenderState`
держит рядом с целевыми гейнами достигнутые и за буфер доводит множитель от
одних к другим. Без этого смена громкости давала разрыв в волне на границе
буфера — щелчок при резком движении слайдера и дребезжание при медленном.
Достигнутые гейны принадлежат только аудиопотоку, поэтому лока не требуют.

Считает это `vDSP_vrampmuladd` — разгон, умножение и накопление одной
операцией. Каналы у нас чередуются, то есть шаг больше единицы (не самый
выгодный случай для векторизации), и всё же замер даёт ускорение в 2–3 раза
против скалярного цикла при идентичном результате.

Гейны обновляются без лока. Лок в `RenderState` защищает раскладку каналов, а
она меняется только при пересборке; движение слайдера меняет одни значения, и
брать под них лок нельзя: realtime-поток заходит через `trylock` и на неудачу
отдаёт буфер тишины. При шестидесяти обновлениях в секунду это давало слышимые
провалы. Отдельное выровненное 32-битное сохранение атомарно, так что порвать
значение нечем.

Пересборка агрегата дебаунсится несимметрично: появление таппа применяется
сразу, исчезновение — через 1,5 секунды. Ждать появления нельзя — пока таппа
нет, приложение играет в полную громкость, и слайдер выглядит залипшим.
Исчезновение же стоит придержать надолго: слайдер у отметки 100% легко
пересекает её туда-обратно много раз подряд, и с короткой задержкой каждое
пересечение успевало снять тапп и создать заново.

Общий clock domain → нет ресемплинга и дрейфа. Латентность = один буфер (~5 мс).
Feedback loop невозможен: таппы exclusive, наш собственный рендер в них не входит.

**Перехват нужен приложению, если у него меняется громкость (не 100% или mute)
ЛИБО если оно выведено не туда, куда выводит система** — маршрутизации без
перехвата не существует. Остальные играют мимо нас нативно; если таких, кому
нужен tap, нет, агрегаты уничтожаются, IOProc останавливаются, потребление CPU
падает до нуля.

Уже созданный tap не снимается, пока приложение звучит. Снятие переключает его
с нашего рендера обратно на родной выход, и этот переход двух путей слышен
разрывом — именно он рвал звук при возврате громкости на 100%. Tap держится до
тишины: в тишине переключение никто не услышит, а `isRunningOutput` как раз и
говорит, когда она наступила.

Громкость устройства движок читает сам, отдельно для каждого маршрута: наш
рендер идёт мимо регулятора устройства, поэтому иначе приложение, уведённое в
наушники, играло бы там на полной шкале независимо от их регулятора.

### Панель

Собрана по образцу системной панели «Звук» из Control Center: заголовок, один
слайдер между двумя динамиками, список приложений, подвал. Между секциями —
`Divider` с отступами от краёв, фон — материал, цвета только системные
(`secondary`, `tertiary`, `quaternary`, `accentColor`).

Устройство вывода — кнопкой `airplayaudio` в строке слайдера, а не отдельной
секцией: секция «Выход» занимала полсотни точек высоты ради одной строки,
которую и так видно по значку.

В строке приложения порядок элементов — иконка, название, слайдер, mute,
устройство вывода. Все размеры собраны в `RowMetrics`; он не набор констант, а
значение, которое считается от настроек — ширина панели, высота строки и
наличие кнопки вывода настраиваются.

Слайдер держит 165 pt и своей длины не меняет: считать его по остатку
заманчиво, но тогда он прыгает вбок каждый раз, когда в списке появляется
приложение с длинным именем. Свободная ширина панели достаётся названию — и
только если названию не хватает минимума (69 pt), слайдер уступает ей место.

Ширина панели, высота строки и число строк до прокрутки настраиваются, значок
устройства в строке можно выключить. Что из этого следует:

| Панель | Значок | Название | Слайдер |
|---|---|---|---|
| узкая 320 | есть | 69 | 125 |
| обычная 360 | есть | 69 | 165 |
| обычная 360 | нет | 94 | 165 |
| широкая 420 | есть | 129 | 165 |

Имя, которому не хватило колонки, обрезается и показывается целиком подсказкой
при наведении — той же, что и проценты у ручки слайдера.

Фон панели переключается в настройках: «Прозрачное» — `.ultraThinMaterial`,
как в системных панелях, «Однотонное» — `.thickMaterial`, сквозь который почти
ничего не видно. Тема и фон выбираются миниатюрами, как в разделе «Оформление»
системных настроек: у темы половина картинки светлая, половина тёмная, у фона
под панелью нарочно пёстрый градиент — на однотонном разницы между материалами
не увидеть вовсе.

Залитая часть слайдера белая на тёмной теме и тёмная на светлой: чистая белая
на светлом треке сливается с ним, и понять, где кончается заполнение, можно
было бы только по ручке.

### Настройки

Настройки — своё окно (`SettingsPanelController`), которое открывается слева
от панели микшера. Вкладки и размер 480×360 — как было.

Сцена `Settings` не подошла: обычное окно забирает фокус, а панель менюбара
система закрывает, как только фокус уходит. Настраивать приходилось вслепую —
чтобы увидеть результат, надо было закрыть настройки и открыть панель заново.

Поэтому окно здесь своё, `NSPanel`, который принципиально не становится
ключевым: `.nonactivatingPanel` — клик не активирует приложение,
`becomesKeyOnlyIfNeeded` — фокус берётся, только если он нужен контролу, а
таких у нас нет (тумблеры, слайдеры и меню работают и без него). Панель
микшера фокус не теряет и остаётся на экране.

Появляется без анимации (`animationBehavior = .none`) и на уровне
`.popUpMenu` — ниже уровнем окно уезжало бы под панель микшера. Если слева
места на экране нет, открывается справа.

Вкладки — настоящий `NSToolbar` со стилем `.preference`. Привычный вид
настроек со значками давала именно сцена `Settings`: она превращала
SwiftUI-шный `TabView` в панель инструментов. В своём окне тот же `TabView`
рисуется обычным сегментированным переключателем без значков, поэтому панель
инструментов здесь собрана вручную, а `SettingsTab` держит перечень вкладок.

### Управление строкой

Проценты показываются подсказкой над ручкой слайдера — и только когда курсор
на самой ручке, а не где-то по треку. В строке для них места нет: слайдер
занимает всю ширину до кнопок.

Рисует подсказку не слайдер, а панель, через `anchorPreference`: изнутри списка
её обрезает `ScrollView` (у верхней строки она уходила за край и показывалась
наполовину), а внутри строки не хватает высоты. Во время перетаскивания
подсказка держится за ручку — курсор к тому моменту может уехать за пределы
слайдера, а число должно оставаться там, где значение.

Видимая область списка настраивается — 3, 4,5, 6 или 8 строк. По умолчанию
4,5: половина строки сразу говорит, что список продолжается, иначе о прокрутке
можно и не догадаться.

Двойной клик — заглушить или включить обратно. Одиночный намеренно ничего не
делает: он принадлежит слайдеру и кнопке динамика внутри строки. Правая кнопка
открывает меню (сброс на 100%, mute, закрепление, «Источник» с выбором
устройства), порядок меняется перетаскиванием.

Список устройств вынесен в `OutputDevicePicker` и используется дважды — кнопкой
в строке и подменю «Источник». Одна логика на оба: два независимых списка рано
или поздно разошлись бы в поведении. Подменю нужно ещё и потому, что кнопку в
строке можно выключить в настройках — тогда правая кнопка остаётся
единственным способом увести приложение.

Строка, из которой не идёт звук, серая — и заглушённая, и выведенная слайдером
в ноль (`AudioAppState.isSilent`): на слух это одно и то же состояние.
Различаются они подписью — «Выкл.» против «0%», потому что mute помнит прежний
уровень, а ноль не помнит. Слайдер при этом выключается только на mute: на нуле
он обязан остаться живым, иначе громкость неоткуда поднять.

### Устройство вывода для приложения

Значок вывода в строке открывает список устройств с пунктом «Как в системе».
Выбор запоминается по bundle ID и переживает перезапуск приложения.

Значок виден всегда, а у приложения, уведённого на другое устройство, ещё и
горит акцентным цветом: о таком маршруте легко забыть и потом долго искать,
почему звук идёт не туда.

Свои агрегаты отфильтрованы из списка устройств по префиксу UID:
`kAudioAggregateDeviceIsPrivateKey` прячет их от ЧУЖИХ процессов, но не от
своего, и без фильтра AudioMixer предлагался бы как выход — звук можно было бы
завернуть в нас же самих.

Приложение с чужим устройством таппится даже на 100% громкости — перенести
звук, не перехватив его, нельзя. Смена системного устройства уводит за собой
только тех, у кого своего выбора нет.

### Порядок строк

По умолчанию порядок автоматический: сверху те, кто звучит прямо сейчас. Строку
можно перетащить мышью — тогда порядок становится ручным и запоминается по
bundle ID. Кнопка со стрелкой в заголовке секции возвращает автоматический.

Перетаскивание сделано обычным `DragGesture`, а не `.draggable`/`.dropDestination`:
системный drag'n'drop поднимает сессию через пастборд и завязан на фокус окна, а
панель `MenuBarExtra` — неактивирующееся окно, которое закрывается при потере
фокуса. Внутренний жест за пределы окна не выходит.

Сохраняется не снимок видимого списка, а порядок, в который вплетены и закрытые
приложения (`AppOrderStore.apply`): иначе закрытый Spotify после перестановки
соседей уезжал бы в конец списка. Движку порядок безразличен — `applyUnsafe`
сравнивает *множества* pid, поэтому перестановка не пересобирает агрегат и не
даёт щелчка в звуке.

У краёв списка работает автопрокрутка. Прокрутка считается не в точках, а в
строках: `autoScrollShift` прибавляется и к смещению строки, и к целевому
индексу, поэтому строка остаётся под курсором, а точка вставки едет вместе с
содержимым. Позиция курсора берётся в системе координат видимой области
(`AppListView.viewportSpace`), а не содержимого — содержимое во время
автопрокрутки движется само.

### Закрепление

Правая кнопка на строке → «Закрепить». Строка поднимается в самый верх и там
фиксируется — порядок становится ручным даже если она уже была первой, иначе
автоматический порядок увёл бы её вниз, стоит зазвучать соседу. Открепление
возвращает строку на прежнее место.

Место запоминается соседом (`PinAnchor`), а не номером позиции: список живёт
своей жизнью, и через час третья строка — уже не то же самое место. Возврат
ищется в сохранённом порядке, а не в видимом списке, поэтому работает и когда
сосед за это время закрылся. Если пользователь передвинул строку сам, якорь
сбрасывается — его выбор важнее прежнего места.

Закреплённые держатся вверху одной группой, и строки между группами не
смешиваются: закреплённые переставляются только между закреплёнными, остальные
— между остальными. Единственную закреплённую строку двигать некуда, и жест для
неё выключен совсем — иначе она поднималась бы под курсором, чтобы тут же
упасть обратно. Без этого правила «закрепить» означало бы всего лишь «один раз
поднять наверх»: любой сосед, начав играть или переехав перетаскиванием, тут же
оттеснил бы закреплённое вниз.

Закреплённое приложение остаётся в списке после закрытия — бесцветной строкой
(`saturation(0)`), которой можно заранее выставить громкость: она сохранится и
применится при запуске.

Такие строки собираются из `VolumeStore` (`offlinePinnedApps`), имя и иконка
берутся из сохранённых настроек и бандла на диске. В движок они не уходят: pid
у них невалидный, и tap на него не навесить.

Поле `isPinned` добавлено в `StoredAppSettings` вместе с рукописным
`init(from:)`. Синтезированный декодер Swift **не** подставляет значения по
умолчанию для отсутствующих ключей — он бросает `keyNotFound`, а `VolumeStore` в
ответ блокирует запись, и выглядит это как «пропали все сохранённые громкости».
Новые поля добавлять только через `decodeIfPresent`.

### Ограничения, которые нельзя обойти

- **App Sandbox выключен** → Mac App Store недоступен, только Developer ID + notarization.
- Появление и снятие tap слышно переключением между нашим рендером и родным
  выходом приложения. Убрать нельзя, можно только выбирать момент: снятие
  откладывается на 1,5 секунды и ждёт тишины, поэтому на слух остаётся один
  переход — при первом движении слайдера от 100%.
- Устройства с цифровым выходом (HDMI, оптика, часть DAC) не поддерживают
  программную регулировку — мастер-слайдер для них деактивируется. Прежде чем
  так решить, `SystemVolumeController` перебирает все места, где громкость
  может лежать: мастер-элемент выходной области, каналы стереопары, затем то же
  в глобальной области. Одного мастер-элемента мало — у Bluetooth-гарнитур его
  обычно нет вовсе, и такое устройство ошибочно считалось нерегулируемым.
  Что именно нашлось, видно в логе категории `Devices`.

## Дальше по плану

      формата настроек, — и всё это проверялось одноразовыми скриптами, которые
      с проектом не остались.
- [ ] **Мягкое ограничение в конце `render`** — единственный оставшийся
      скалярный проход. Кандидат на ранний выход через `vDSP_maxmgv`, но
      выигрыш не мерян, так что это гипотеза, а не задача.
- [ ] **Локализация** — строки захардкожены по-русски.

## Что проверялось и как

Замеры и проверки логики делались одноразовыми программами, а не на глаз.
Результаты, на которые опирается код:

| Что | Результат |
